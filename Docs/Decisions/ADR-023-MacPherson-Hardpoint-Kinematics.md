# ADR-023 — MacPherson hardpoint kinematics provider

**Status:** Accepted — SUS02  
**Date:** 2026-08-09

## Decision

Heritage Engine exposes `macpherson_strut_v1` as a reusable native suspension
provider. The provider is selected per suspension component/corner and therefore
can coexist with other suspension mechanisms on the same vehicle.

A runnable MacPherson corner requires these eight chassis-local reference
hardpoints:

- `strut_top_mount`
- `strut_upright_mount`
- `lower_arm_inner_front`
- `lower_arm_inner_rear`
- `lower_ball_joint`
- `tie_rod_inner`
- `tie_rod_outer`
- `wheel_center`

The native compiler rejects an active MacPherson component if any required point
is absent or if the resulting linkage is degenerate. Missing hardpoints remain
valid only while another provider (for example `linear_raycast_v1`) is selected.

## Kinematic model

`MacPhersonKinematics.cpp` owns the mechanism-specific geometry. At each
high-rate suspension evaluation it:

1. treats the two lower-arm inner points as the rigid control-arm hinge axis;
2. rotates the lower ball joint around that axis to satisfy suspension travel;
3. updates the steering-axis line from the lower ball joint to the fixed strut
   top mount;
4. carries the rigid upright reference points/basis through the resulting
   steering-axis change;
5. solves the fixed-length tie rod for passive bump-steer correction;
6. applies commanded road-wheel steering around the current steering axis;
7. derives camber/toe, strut compression, wheel-centre position and the
   instantaneous strut/spring motion ratio from the hardpoint geometry.

The instantaneous motion ratio is consumed by the existing nonlinear
spring/damper force provider, so the spring/damper wheel rate changes with the
linkage rather than remaining a fixed authored ratio.

## Scope boundary

SUS02 remains a raycast-wheel suspension model, not a general-purpose multibody
finite-element suspension solver. It does not yet solve structural loads through
every arm/bushing, compliance steer, chassis pickup-point elasticity, or an
exact curved wheel-path/road intersection query. Those are future extensions.

The important contract is that alignment and spring motion are now generated by
actual linkage geometry rather than fabricated travel curves when this provider
is active.

## Peugeot 206 RC policy

The Peugeot-oriented prototype declares MacPherson architecture at the front,
but it must stay on `linear_raycast_v1` until authoritative per-corner hardpoint
positions are supplied from measured/reference data or vehicle-asset authoring.
The engine must never invent plausible-looking Peugeot hardpoints merely to
activate the provider.
