# STUDIO13 — Operational Traffic & Navigation

STUDIO13 builds directly on STUDIO12 and does not retire the existing road-spline or low-level HROAD graph workflows.

## Authoring additions

- HROAD v4 with HROAD v1/v2/v3 backward loading.
- Semantic graph links: Travel, Lane Change, Merge, Junction Turn, Parking Access, Spawn Access.
- Generated lane nodes carry road/lane/direction metadata while manual graph nodes remain valid overrides.
- Automatic adjacent-lane change edges are generated by the road compiler; manual edges with the same movement take precedence.
- Driving-side and car-following policy: left/right traffic, keep-side behavior, following gaps, acceleration/braking, lane-change cooldown/gaps and route costs.
- Traffic streaming policy: full/simplified/dormant radii, sector size, spawn/despawn budgets and dormant persistence.
- Per-intersection signal controllers: Fixed Time, Actuated and Adaptive, detector range, green bounds, gap-out, queue adaptation and emergency preemption.
- Turn connectors gain conflict groups and reservation duration for intersection occupancy arbitration.
- Runtime road restrictions: closures, incidents, construction, event closures, tolls, low-emission restrictions, mass limits and height limits, with schedules and route-cost/speed effects.
- Validator coverage for semantic link costs, controller references, streaming radius ordering, maneuver reservations and restriction targets.

## Racing United runtime

`Runtime/TrafficOperations.lua` consumes Studio-generated data and provides:

- restriction-aware graph routing;
- runtime restriction overrides for incidents/events;
- traffic streaming tier selection;
- fixed/actuated/adaptive traffic-light phase progression;
- emergency signal preemption hooks;
- intersection conflict-group reservations;
- emergency-yield decisions.

This layer is intentionally data-driven so future traffic-vehicle AI can consume one authoritative road/navigation package rather than duplicating road logic.
